Outbox pattern demo

Orders API (service A) doesn't call Shipping: it saves the order and an OrderPlaced event row in one database transaction. The outbox relay worker reads that table and publishes to Azure Service Bus, and the dispatcher takes each message from the queue and calls the Shipping API (service B), which deduplicates by message id. Compare it with the naive endpoint, which commits and then calls Shipping directly.

Try it

Makes the Shipping API answer 503: watch the dispatcher retry until Service Bus dead-letters the message. Stop the shipping, dispatcher or servicebus resources in the Aspire dashboard to simulate outages.
The dispatcher "crashes" after Shipping did the work but before completing the message. Service Bus redelivers it, and the second delivery must not create a second shipment.
